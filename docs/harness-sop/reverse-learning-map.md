# 逆向学习地图（Reverse-Learning Map）

本文件把"用 reverse 技能消化吸收开源项目"固化为 SOP 的**可复用方法**。它是 `vendor/reverse-skill`
开源形态（源码/机制研读）的学习版：目标不是审计漏洞，而是把一个技术方向的**机制真相**吸收进
对标分析。首个完整应用见
[examples/memory-tiring-p2v/reverse-digest.md](examples/memory-tiring-p2v/reverse-digest.md)。

## 方法要点

1. **按"逆向学习价值"排序，不按 star**。先读"能跑起来、能对上论文/方向概念"的上游代码（P0），
   再读观测与放置工具（P1）、问题源头（P2），最后才是模拟器与论文原型（P3）。
2. **每个仓库只回答一个问题**。进仓库前先写下这个"逆向问题"，读到能回答就停，不通读。
3. **四分法归位**：每个仓库改变的只会是——**观测 / 布局 / 放置 / 回收目标** 之一（四者全改的仓库
   不存在）。读完必须能把它放进这四格之一。
4. **指定读法路径**：不从入口通读；按一条与问题相关的调用链走（如内核按"观测→回收→分层→驱动"）。
5. **闭环收束**：最后把领域/论文名词**贴回函数与机制**；贴不上的部分，就是论文相对上游的**增量**
   ——这正是对标分析里"学术热点对设计的含义"的来源。
6. **纪律沿用 SOP**：用户给的课程清单是**线索**（仓库存在性、路径、命名须核验）；机制结论对
   **一手源**（源码/官方文档）核验；未运行只研读的，要如实标注"阅读式逆向"。
7. **显式维护"暂缓清单"并写明理由**：不在本轮读的仓库也要留档、给出缓读依据，防止后续误判为
   遗漏。两类典型：**路径不同**（如 pmdk——持久内存编程库，与易失扩容/页回收不是同一条路径，
   P0–P2 走完再看）；**思路已入上游**（如 TPP——多数已在主线内核 `mm/`，先读主线、不必先找独立
   仓库）。研究原型仓库名不稳定的（论文级项目），不写死地址、以作者主页/会议 artifact 为准。

## 通用闭环读序（模板）

1. 用观测工具看清"两种数据"（如：热度 vs 带宽是两回事）。
2. 在上游内核/运行时把**一个对象的生命周期**串起来（分配 → 观测 → 判定 → 动作）。
3. 用拓扑工具看"这段资源属于谁"（node/设备/区域）。
4. 回到分配器/运行时上游，确认问题在"进内核之前"是否已经形成。
5. 名词贴回函数；剩下贴不上的=论文增量。

## 产物要求

- 每仓库：`逆向问题 → 源码级答案（带路径/函数锚点）→ 四分法归位 → 与论文/方向的对照`。
- 一张**对象生命周期**机制图（Mermaid，合规）。
- 两张收束表：仓库四分法表；名词→函数映射表（含"论文增量"列）。
- 明确标注哪些是**源码核验**、哪些是**文档核验**、哪些是**阅读式（未运行）**。
